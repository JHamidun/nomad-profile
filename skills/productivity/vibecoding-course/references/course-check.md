# Course Check — проверка миссии

Процедура проверки текущей миссии. Вызывается из driver'а (SKILL.md, шаг 4), когда ученик говорит «проверь», «готово», «я сделал».

Пути как в SKILL.md: **CONTENT** = `${HERMES_SKILL_DIR}/references/content` (read-only), **HOME** = вывод `python ${HERMES_SKILL_DIR}/scripts/_course_home.py` (writable: `state.json`, `sandbox/`).

Ты проверяешь артефакт миссии честно и доброжелательно. Проверка — не экзамен на отсев, а способ убедиться, что вещь реально работает. Но и не формальность: не пройдено — значит не пройдено, с объяснением, что дочинить.

## Шаг 1. Найди, что проверять

1. Прочитай `<HOME>/state.json` → `track`, `current_mission`.
2. Открой файл миссии `<CONTENT>/tracks/<track>/<current_mission>.md`.
3. Найди раздел `## Проверка` — в нём блок `CHECKS:` (список проверок) и `PASS_THRESHOLD:` (порог в процентах; если не указан — возьми `pass_threshold_default` из `<CONTENT>/config.yaml`).

## Шаг 2. Исполни проверки (офлайн, без секретов)

Пути артефактов в блоках CHECKS даны относительно рабочей папки ученика — это `<HOME>/sandbox/` (например `sandbox/about-me.md` → `<HOME>/sandbox/about-me.md`). Типы проверок:

| Тип | Формат строки | Как исполнять | Зачёт |
|---|---|---|---|
| `file_exists` | `- file_exists: <путь>` | Проверь, что файл (или папка) существует | существует |
| `contains` | `- contains: <файл> :: "<признак>"` | Прочитай файл, ищи подстроку-признак без учёта регистра | файл есть и признак найден |
| `runs` | `- runs: "<команда>"` | Выполни команду из рабочей папки ученика (`<HOME>/sandbox/`) | код возврата 0 |
| `manual` | `- manual: "<что показывает ученик>"` | Попроси ученика показать/рассказать указанное; оцени по существу | наставник подтверждает |

Правила исполнения:

- `runs` — выполняй только команду из файла миссии, как написана. Команда падает — покажи её вывод ученику как материал для разбора, это не «ошибка проверки», а подсказка.
- `runs` с `python`: единственное допустимое отклонение от «как написана» — имя интерпретатора. Нет команды `python` — выполни тот же скрипт через `python3` (macOS/Linux) или `py` (Windows); зачёт тот же. На macOS не зови `python3` вслепую: если `xcode-select -p` падает и другого питона в системе нет — НЕ запускай (всплывёт системный диалог установки инструментов разработчика), отметь проверку как непройденную и предложи ученику поставить Python вместе с тобой.
- `runs` с git-историей (любой `runs: git ... log`) — обязательный предварительный шаг: сперва убедись, что репозиторий лежит именно в целевой подпапке, то есть в ней есть `.git` (например, `<HOME>/sandbox/project/.git`). Если `.git` в целевой папке нет — git молча поднимется к родительской папке и команда «успешно» покажет чужую историю — это ложный зачёт. В таком случае отметь проверку как непройденную и объясни ученику: git-репозиторий в папке проекта ещё не создан.
- `manual` — не превращай в допрос. Один вопрос, слушаешь ответ, оцениваешь суть, а не формулировки. Ученик отвечает своими словами — это норма.
- Ничего не отправляй в сеть и не проси никаких ключей: базовая проверка полностью локальная.

## Шаг 3. Онлайн-grader (только если настроен)

Прочитай `<CONTENT>/config.yaml` → `grader`. Если `online: true` и `endpoint` непустой:

- перед ПЕРВОЙ отправкой скажи ученику, что результаты проверки уйдут на сервер академии, и спроси согласие; ответ запиши в `<HOME>/state.json` (`"grader_consent": true|false`) и больше не переспрашивай. `false` — работаем только локально;
- отправь на endpoint JSON с результатами: `{course, role, mission, checks: [{type, target, passed}], score_local}`;
- содержимое артефактов прикладывай только там, где в них нет чужих персональных данных. Миссии с потенциальными ПД (HR: скрининг и письма кандидатам; продажи: база лидов) — содержимое файлов НЕ отправляй никогда, только результаты checks и балл;
- ответ grader'а (балл, фидбек) имеет приоритет над локальным баллом.

Если запрос не удался (нет сети, endpoint молчит, любая ошибка) — молча откатись на локальный результат из шага 2 и продолжай. Онлайн — надстройка, офлайн — основа. **В Nomad-порте grader по умолчанию выключен** (`online: false`) — работаешь строго локально.

## Шаг 4. Балл и вердикт

- Все проверки равновесны: `score = round(100 × пройдено / всего)`.
- `passed = score >= PASS_THRESHOLD`.

## Шаг 5. Запиши и отчитайся

1. В `<HOME>/state.json` → `scores["<mission>"] = { "score": N, "passed": true|false, "checked_at": "<ISO>", "feedback": "<одна-две фразы>" }`, обнови `updated_at`. (Поле `completed` двигает driver, не ты.)
2. Отчитайся ученику коротко и предметно:
   - список проверок с ✓/✗ по одной строке;
   - балл и вердикт;
   - если `passed` — что именно получилось хорошо (конкретно);
   - если нет — что дочинить, начиная с самого простого пункта, и предложение проверить снова, когда готов.

Не занижай и не натягивай: проверка, которой можно верить, — половина ценности курса.
