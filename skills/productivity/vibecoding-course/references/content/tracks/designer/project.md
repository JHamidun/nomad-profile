# Миссия 5 (финальный проект) — Свой живой дизайн-проект

ROLE: designer
GOAL: Ученик собирает под ведением агента цельный дизайн-проект по своей рабочей задаче: кликабельный интерактивный прототип + мини дизайн-система (токены, базовые компоненты, принципы) + сгенерированные ассеты — всё связано между собой, лежит в git и готово к показу.
WHY: По отдельности навыки уже есть — живая страница, токены, прототип, ассеты. В работе они нужны вместе: продакт ждёт прототип, разработчику нужна система с токенами и компонентами, а не пачка фреймов, бренду нужна графика в одном стиле. Дизайнер, который приносит всё это одним пакетом, меняет свою роль в команде: из «нарисуй картинку» — в «вот рабочая основа продукта».

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Начни с выбора вещи: спроси, какой реальный проект из его работы собрать (фича продукта, свой сервис, портфолио, внутренний инструмент). Подойдёт и развитие проекта из миссий 1–4, и новая вещь. Если задумка тянет на месяц — вместе ужмите до флоу из 3–4 экранов: финальный проект — это первая цельная версия, не релиз.
- Скажи оценку времени: 90–120 минут, лучше в два подхода (система + прототип в первый, ассеты + сборка во второй; прогресс сохранится).
- Собираем в `sandbox/design/final/`. Веди по слоям, руками ученика:
  1. **План.** Пусть попросит агента составить план в `sandbox/design/final/PLAN.md`: 4–5 шагов, каждый заканчивается чем-то проверяемым, код пока не писать (это цикл из фундамента — атом `../../.course/knowledge/core/01-plan-then-build.md`). Пусть прочитает и поправит словами.
  2. **Мини дизайн-система.** Папка `design-system/`: `tokens.css` (цвета, шкала шрифта, отступы, радиусы — его решения, можно эволюцию токенов из миссии 2), `components.html` — страница с ядром компонентов (кнопка в 2–3 вариантах и состояниях: обычная, наведение, недоступная; поле ввода с ошибкой; карточка; бейдж), и `README.md` — принципы на полстраницы: когда какой цвет, какие отступы, чего не делать. Правило: компоненты берут значения только из токенов.
  3. **Прототип.** Папка `prototype/`: кликабельный флоу из 3–4 экранов его вещи, собранный НА этой системе — подключает те же tokens.css, экраны состоят из тех же компонентов, у ключевого экрана есть empty- и error-состояния. Работает офлайн из файла.
  4. **Ассеты.** Папка `assets/`: стиль-спека, иконки, которые реально используются в прототипе, логотип, фавиконка — по механике миссии 4. Фавиконка подключена к прототипу.
  5. **Сборка и страховка.** Пусть попросит агента завести git-репозиторий в `sandbox/design/final` и коммитить после каждого слоя (система → прототип → ассеты) с понятными сообщениями — привычка из фундамента. В конце — пусть попросит показать историю и увидит свои точки возврата.
  6. **Прогон-демо.** Финальный тест — ученик сам, без агента: открыть components.html — компоненты на месте; открыть прототип — прокликать флоу и показать состояния; поменять в tokens.css акцентный цвет — перекраситься должны И компоненты, И прототип; открыть витрину ассетов. Если на любом шаге споткнулся — правка агенту, и прогон заново.
- Точки помощи: система расползается (десятки компонентов) → ядро из 4 компонентов достаточно, остальное появится из реальных нужд; прототип не перекрашивается вместе с токенами → где-то остались захардкоженные значения, пусть попросит агента найти в стилях прототипа значения мимо tokens.css; всё сломалось после большой правки → git на месте: «покажи, что изменилось» / «откати к последнему коммиту» (в Claude Code есть и /rewind); устал и хочет бросить на середине → зафиксируй коммитом, что готово, и продолжите в следующий заход — это нормальный режим, не провал; хочет опубликовать → отлично, механика деплоя знакома из фундамента (атом `../../.course/knowledge/core/05-deploy.md`), но проверка проекта этого не требует.
- Назови типичное заблуждение вслух: «дизайн-система — это месяцы работы дизайн-отдела» — минимально жизнеспособная система (токены + 4 компонента + страница принципов) собирается за вечер и уже работает: его прототип тому доказательство.
- В конце — вызови проверку и, если passed, поздравь по-настоящему и конкретно: он пришёл с макетами, которые молчат, а уходит с живым прототипом на собственной дизайн-системе, с графикой в одном стиле и историей изменений. Скажи прямо: этот пакет можно показывать команде, клиенту или в портфолио — и это сделано его руками за курс.

## Ученику (живой сценарий)

«Представь: в команде объявили ревизию процессов, и у тебя есть шанс показать, как может выглядеть работа дизайнера теперь. Не слайды с рассуждениями — работающий пакет: прототип, который кликается, система, из которой он собран, графика в одном стиле. Одна папка, которая отвечает на все вопросы продакта, разработчика и бренда. Собираем её.» (~90–120 минут, спокойно делится на два подхода)

Что делаем руками:

1. Выбери вещь из своей работы и попроси агента составить план в `final/PLAN.md` — 4–5 проверяемых шагов, без кода. Прочитай, поправь словами.
2. Собери мини дизайн-систему в `final/design-system/`: токены (твои решения о цвете, шрифте, отступах), страница компонентов — кнопка, поле ввода, карточка, бейдж с их состояниями, и README с принципами на полстраницы. Компоненты живут только на токенах.
3. Собери в `final/prototype/` кликабельный флоу из 3–4 экранов — на этой же системе: те же токены, те же компоненты. Ключевому экрану — empty- и error-состояния.
4. Добавь в `final/assets/` графику по своей стиль-спеке: иконки, которые реально стоят в прототипе, логотип, фавиконку.
5. Страхуйся по ходу: git-репозиторий в `final/`, коммит после каждого слоя.
6. Устрой себе демо: прокликай флоу, переключи состояния, поменяй акцентный токен — и посмотри, как перекрашивается всё разом. Это твой момент.

В конце у тебя не учебная поделка, а пакет, который можно показать команде в понедельник.

## Артефакт

Папка `sandbox/design/final/` с:
- `PLAN.md` — план из проверяемых шагов;
- `design-system/` — `tokens.css`, `components.html` (ядро компонентов с состояниями), `README.md` (принципы);
- `prototype/` — кликабельный флоу из 3+ экранов на токенах и компонентах системы, с empty/error-состояниями ключевого экрана;
- `assets/` — стиль-спека, иконки, логотип, фавиконка (подключена к прототипу);
- git-история минимум из 3 коммитов (по слоям).
