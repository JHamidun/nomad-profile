# Финальный проект — Кампания под ключ

ROLE: marketer
GOAL: Ученик собирает из наработок трека связный продукт — лендинг кампании + авто-контент + дашборд метрик, — с планом, хабом-оглавлением, git-историей и (по желанию) публичной ссылкой. И показывает сквозной путь: пост с UTM-ссылкой → лендинг → форма с метками → данные → дашборд.
WHY: По отдельности лендинг, посты и дашборд — это заготовки. Кампанией они становятся, когда связаны: из поста можно кликнуть на лендинг, заявка приезжает с источником, дашборд отвечает, куда девать бюджет. Именно связную систему маркетолог показывает руководителю или клиенту — и именно она отличает «поигрался с ИИ» от «собрал себе рабочий инструмент». Это и есть цель всего трека.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Начни с инвентаризации: открой с учеником `sandbox/marketing/` и вместе посмотрите, что уже есть (utm/, campaign/, content/, dashboard/). Спроси: это всё ещё та кампания, которую он реально запускает? Если кампания сменилась — не страшно: план учтёт обновление оффера и постов, конвейер из миссии 5 как раз для этого.
- Скажи оценку времени: 90–120 минут, удобно в два подхода (сборка + git/деплой). Прогресс сохраняется.
- Веди полным циклом из миссии 2 — план → сборка по шагам → git → деплой:
  1. **План.** Пусть попросит агента: «осмотри sandbox/marketing/ и составь план в `sandbox/marketing/PLAN.md`: 3–5 шагов (каждый пункт озаглавь «Шаг N»), каждый заканчивается чем-то проверяемым; пока ничего не меняй». В плане должны оказаться: хаб-оглавление, доведение частей до текущей кампании, сквозная связка, git. Пусть прочитает план и поправит словами — это его точка контроля (атом `01-plan-then-build.md`).
  2. **Хаб.** `sandbox/marketing/index.html` — одна страница кампании: название и оффер одной строкой, ссылки на лендинг, посты и дашборд, статус запуска. Это то, что не стыдно скинуть руководителю одной ссылкой.
  3. **Сквозная связка.** Пусть проверит руками весь путь: открыл посадочную по UTM-ссылке из поста (собранной своим генератором) → форма знает источник → канал из этой ссылки есть в data.csv → дашборд его считает. Что-то порвано (в постах ссылки без меток, в data.csv другие названия каналов) — чинит с агентом. Названия каналов везде по словарю из utm-rules.md.
  4. **Git.** «Сделай из sandbox/marketing git-репозиторий и закоммить с понятным сообщением». Дальше — коммит после каждого осмысленного шага, минимум три. Пусть попросит показать историю (агент выполнит `git log --oneline`) и увидит точки возврата.
  5. **Деплой (по желанию, как в миссии 2).** Есть интернет и желание — «опубликуй кампанию самым простым бесплатным способом»; логинится ученик сам, ссылку — в `sandbox/marketing/DEPLOY.md`, открыть с телефона. Нет — в DEPLOY.md пишем «локально» и каким файлом открывать; это не провал.
- Точки помощи: план разбух до 10 шагов → ужать до 5, остальное — после курса; хочется переделать лендинг «по-нормальному» → одна-две правки по критериям из миссии 4, перфекционизм — враг запуска; в постах и data.csv разные названия каналов → единый словарь utm-rules.md, пусть агент выровняет; git ругается на имя/почту → пусть покажет ошибку агенту, тот настроит git config; страх «сломаю собранное» → после первого коммита показывай откат: «покажи, что изменилось» / «откати к последнему коммиту».
- Назови типичное заблуждение вслух: «инструменты собрал — кампания готова» — нет: система живёт, пока в ней один словарь имён и работающие связки; порвалась разметка — дашборд снова врёт.
- В конце — вызови проверку и, если passed, поздравь по-крупному, но конкретно: перечисли, что он собрал руками за трек (генератор, лендинг, конвейер, дашборд, хаб) и что весь этот стек — его, работает офлайн и переносится на следующую кампанию заменой source.md и offer.md. Трек пройден.

## Ученику (живой сценарий)

«Представь: в пятницу тебя просят показать кампанию клиенту — не «что запланировано», а как это работает. У тебя уже всё есть: генератор ссылок, лендинг, конвейер контента, дашборд. Осталось собрать это в одну вещь, которую открываешь одной ссылкой и ведёшь по ней рассказ: вот пост, вот куда он ведёт, вот цифры и решение по бюджету.» (~90–120 минут, можно в два подхода)

Что делаем руками:

1. Попроси агента осмотреть `sandbox/marketing/` и составить план сборки в `PLAN.md`: 3–5 проверяемых шагов, пока без изменений. Прочитай и поправь словами.
2. Иди по плану. Собери хаб `sandbox/marketing/index.html`: оффер одной строкой, ссылки на лендинг, посты, дашборд.
3. Прогони сквозной путь как твой клиент: клик по UTM-ссылке из поста → лендинг открылся → форма знает источник → этот канал виден на дашборде. Порвано — чини с агентом, названия каналов везде по твоему словарю.
4. Застрахуйся: git-репозиторий в `sandbox/marketing`, минимум три коммита по ходу, история — твои точки возврата.
5. Хочешь — публикуй и записывай ссылку в `DEPLOY.md` (регистрируешься и логинишься ты). Не хочешь или нет интернета — пиши «локально»: показ с ноутбука тоже показ.

В пятницу ты открываешь одну ссылку и показываешь кампанию целиком — от поста до решения по бюджету.

## Артефакт

Папка `sandbox/marketing/` как связный проект: `PLAN.md` (план из проверяемых шагов), `index.html` (хаб со ссылками на лендинг, контент и дашборд), доведённые части из миссий 3–6, git-история минимум из 3 коммитов и `DEPLOY.md` (публичная ссылка — или пометка «локально»).
