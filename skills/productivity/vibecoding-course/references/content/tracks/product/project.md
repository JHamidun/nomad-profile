# Миссия 7 — Финальный проект: MVP + дашборд для product-совета

ROLE: product
GOAL: Ученик собирает под ведением агента полный пакет продакта: кликабельный MVP-прототип своей фичи и дашборд продуктовых метрик к нему — через план, сборку по шагам, git и 5-минутное демо.
WHY: Это защита инициативы — момент, где решается, дадут ли твоей идее команду и квартал. Слайды с обещаниями там видели сто раз. Пакет «вот MVP, пощёлкайте — вот метрики, по которым поймём, что взлетело» выигрывает у любого деки, потому что отвечает на оба вопроса совета: «как это будет работать?» и «как поймём, что не зря?».

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Сначала выбор вещи: фича из его бэклога (m03), прошедшая проверку гипотезой (m04), — идеальный кандидат, но живая инициатива из текущей работы подходит не хуже. Проверь масштаб: если тянет на продукт целиком — ужмите до одного основного пути, MVP это и есть.
- Скажи оценку времени: 90–120 минут, можно в два подхода (прототип и дашборд — разными заходами; git страхует прогресс).
- Это финал: ученик уже всё умеет — твоя роль сместиться из ведущего в заказчика-наблюдателя. Подсказывай, только когда просит или буксует.
- Ход по шагам:
  1. **План.** Пусть попросит агента составить `sandbox/mvp/PLAN.md`: 4–6 шагов (каждый пункт озаглавь «Шаг N»), каждый заканчивается чем-то проверяемым, код после утверждения плана. Пусть прочитает и поправит словами — как в миссии 2 фундамента.
  2. **MVP-прототип.** `sandbox/mvp/index.html` плюс экраны, связанные ссылками: основной путь из 2–4 шагов, пустое состояние, реалистичные данные (всё как в m05, теперь без подсказок). Хочет живости — пусть попросит агента намерением: «чтобы введённое на первом экране появлялось на следующем», как это сделать — забота агента.
  3. **Git.** После первого работающего состояния — репозиторий в `sandbox/mvp` и коммит; дальше коммит после каждого осмысленного шага. Минимум два.
  4. **Дашборд.** `sandbox/mvp/dashboard.html` — метрики именно этого MVP: North Star, воронка основного пути, пороги успеха. Данных у нерождённой фичи нет — пусть попросит агента сгенерировать модельные 8 недель «как будто фича живёт» и честно подпишет на дашборде, что данные модельные, а пороги — настоящие. Требования те же, что в m06: открывается из файла, без сети, данные запечены.
  5. **DEMO.md.** Сценарий на 5 минут: какая боль и гипотеза → путь по MVP (какие экраны кликаем и что показываем) → дашборд (какие метрики и какие пороги скажут, что фича взлетела) → чего просим у совета (команду, спринт, бюджет).
  6. **Деплой (опционально).** Есть интернет и желание — пусть попросит агента опубликовать самым простым бесплатным способом, как в миссии 2 (логинится ученик, агент не вводит пароли), ссылку — в DEMO.md. Без интернета — пометка «локально», это не провал.
  7. **Прогон.** Ученик прогоняет демо по DEMO.md целиком, ты — совет: один вопрос по флоу, один по метрикам. Затем проверка.
- Точки помощи: план разросся → 4–6 шагов, остальное в раздел «потом»; застрял в полировке экранов → напомни: совет смотрит на путь и метрики, а не на тени у кнопок; дашборд про «регистрации и визиты», хотя MVP про другое → верни к вопросу «какая метрика докажет ценность именно этой фичи?»; что-то сломалось и страшно чинить → git-история для того и есть: пусть попросит агента показать, что изменилось, или откатить к последнему коммиту; сложно придумать пороги → пусть возьмёт порог из hypothesis.md (m04) и адаптирует.
- Назови типичное заблуждение вслух: «MVP — это урезанный продукт, стыдно показывать». MVP — это инструмент ответа на вопрос, и хорош тот, который отвечает быстрее всех. Совету нужен не блеск, а уверенность, что ты знаешь путь пользователя и критерии успеха.
- В конце — вызови проверку и, если passed, финальная похвала — предметно, по всей цепочке: фидбек → гипотеза → прототип → метрики → MVP с демо. Это рабочий цикл продакта на агенте, и он у ученика теперь в руках.

## Ученику (живой сценарий)

«Представь: через неделю product-совет, где решается судьба твоей инициативы — дадут команду и квартал или отправят "доработать идею". Дека с обещаниями там уже никого не убеждает. Ты приходишь с другим: MVP, который можно пощёлкать, и дашборд, где видно, чем ты измеришь успех. Собираем этот пакет.» (~90–120 минут, можно в два подхода)

Что делаем руками:

1. Выбери вещь: топ твоего бэклога, прошедший проверку гипотезой, — или живая инициатива из работы. Попроси агента составить `sandbox/mvp/PLAN.md` — 4–6 проверяемых шагов, без кода до твоего «поехали». Прочитай, поправь, утверди.
2. Собери с агентом MVP: `sandbox/mvp/index.html` плюс экраны ссылками, основной путь, пустое состояние, реальные данные. Иди по плану шаг за шагом, смотри результат каждого.
3. После первого работающего состояния — попроси агента завести git в `sandbox/mvp` и закоммитить. Дальше — коммит после каждого осмысленного шага.
4. Собери `sandbox/mvp/dashboard.html` — метрики именно этого MVP: North Star, воронка, пороги успеха. Данные модельные (подпиши это на дашборде), пороги настоящие. Работает из файла, без интернета.
5. Напиши `sandbox/mvp/DEMO.md` — демо на 5 минут: боль и гипотеза → путь по MVP → метрики и пороги → чего просишь у совета.
6. Хочешь — опубликуй: попроси агента предложить самый простой бесплатный способ, ссылку в DEMO.md. Без интернета — пометка «локально».
7. Прогони демо целиком, вслух, по DEMO.md. Наставник сыграет совет и задаст пару вопросов.

К концу у тебя есть пакет, с которым выходят к совету, — и повторяемый цикл: следующую инициативу ты соберёшь так же, уже без курса.

## Артефакт

Папка `sandbox/mvp/`: `PLAN.md` (4–6 проверяемых шагов), кликабельный MVP (`index.html` + экраны, пустое состояние, реалистичные данные), `dashboard.html` (North Star, воронка, пороги; модельные данные подписаны), `DEMO.md` (сценарий демо, при деплое — ссылка), git-история минимум из 2 коммитов.

## Дальше

Трек продакта пройден. С собой уносишь цикл: фидбек → бэклог → гипотеза с порогом → прототип → метрики → MVP с демо — и каждый шаг ты умеешь делать руками с агентом за часы, а не спринты. Следующая инициатива из твоей работы — лучший полигон: начни с горы фидбека, как в m03, и пройди цикл без наставника.
