# Миссия 3 — Разведка данных: чужая выгрузка

ROLE: analyst
GOAL: Ученик умеет за полчаса разобрать незнакомый CSV вместе с агентом: что внутри, где грязь, каким числам можно верить.
WHY: Аналитику почти никогда не дают чистые данные. Прилетает выгрузка из CRM, 1С или рекламного кабинета — а через два часа встреча, где по этой выгрузке будут принимать решение. Кто быстро видит дыры в данных, тот не подписывается под выводами из мусора.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Сначала спроси: с какими выгрузками он имеет дело в работе (CRM, продажи, реклама, опросы, логистика) — примеры переводи на его фактуру. Есть под рукой реальный CSV — работаем с ним, но сначала напомни убрать персональные данные (имена, телефоны, почты заменить или вырезать — привычка аналитика, а не бюрократия). Нет своего файла — пусть попросит агента сгенерировать реалистичную выгрузку продаж в `sandbox/datalab/raw.csv`: 500–2000 строк и типичная грязь — дубли, пропуски, разные форматы дат, лишние пробелы, пара аномальных сумм.
- Скажи оценку времени: 30–40 минут.
- Дай сделать РУКАМИ, по одному микро-шагу:
  1. Инструмент: пусть попросит агента выполнить `python --version`. Python нужен всему треку начиная со следующей миссии; если его нет — пусть агент поможет установить или предложит обходной путь сейчас, а не посреди работы со скриптами.
  2. Первый взгляд: пусть спросит агента «что это за данные?» — колонки, число строк, период, что вообще за сущности. Обрати внимание ученика: агент реально прочитал файл, а не пересказывает название.
  3. Аудит: пусть попросит найти проблемы — пропуски, дубли, разнобой форматов, подозрительные значения. Ключевая привычка: по каждой проблеме просить **пример конкретных строк**, а не только цифру («покажи 3 строки с дублями»).
  4. Масштаб: пусть выберет самую неприятную находку и попросит агента посчитать, сколько процентов строк она затрагивает. Одно дело «есть дубли», другое — «11% строк — дубли».
  5. Фиксация: пусть попросит агента собрать `sandbox/datalab/AUDIT.md` с тремя разделами — ровно с такими заголовками: «Что за данные», «Находки» (минимум 3, каждая с примером и с ответом «чем это грозит выводам»), «Вопросы к владельцу данных». Формулировки находок — учеником, агент оформляет.
- Точки помощи: агент вывалил простыню статистики → пусть ученик сузит запрос: «покажи только проблемы, по каждой — пример строки»; ученик принимает числа на слово → останови: «попроси показать, как посчитано» (атом `analyst/01-check-the-numbers.md`, перескажи в двух предложениях); смущает сгенерированный файл («это же не настоящие данные») → скажи честно: навык разведки тот же, грязь в сгенерированной выгрузке — ровно та, что я годами вижу в реальных.
- Назови типичное заблуждение вслух: «данные из системы = правильные данные». Нет: выгрузка отражает то, как живые люди заполняли поля. Менеджер, который вбил сумму с пробелом, тоже попал в твой CSV.
- В конце — вызови проверку (скилл course-check) и, если passed, похвали конкретно: ещё утром это был непонятный файл, теперь — документ, с которым можно идти к владельцу данных. Открой следующую миссию.

## Ученику (живой сценарий)

«Представь: завтра встреча по итогам квартала. Тебе скинули выгрузку продаж со словами "глянь, там всё есть". Листать восемь тысяч строк в Excel — вечер потерян, а подписываться под чужими числами вслепую не хочется. Есть агент.» (~30–40 минут)

Что делаем руками:

1. Положи свой CSV в `sandbox/datalab/raw.csv` (персональные данные — убрать). Своего файла нет — попроси агента сгенерировать реалистичную выгрузку продаж с типичной грязью: дубли, пропуски, разные форматы дат.
2. Спроси у агента, что это за данные: какие колонки, сколько строк, за какой период. Прочитай ответ и сверь с тем, что ты ожидал(а) увидеть.
3. Попроси найти проблемы в данных. По каждой — требуй пример конкретных строк, не только цифру. «Есть пропуски» — это не находка; «в колонке email пусто у 340 строк из 2000, вот три примера» — находка.
4. Выбери самую неприятную проблему и попроси посчитать её масштаб в процентах.
5. Попроси агента оформить `sandbox/datalab/AUDIT.md`: «Что за данные», «Находки» (минимум три, каждая с примером и ответом «чем грозит выводам»), «Вопросы к владельцу данных». Выводы формулируешь ты — агент записывает.

К концу у тебя есть аудит, с которым не стыдно прийти на встречу: вот данные, вот их слабые места, вот вопросы.

## Артефакт

`sandbox/datalab/raw.csv` (исходная выгрузка) и `sandbox/datalab/AUDIT.md` с разделами «Что за данные», «Находки» (минимум 3 проблемы с примерами) и «Вопросы к владельцу данных».

## Проверка (CHECKS — исполнимо офлайн)

  - file_exists: sandbox/datalab/AUDIT.md
  - contains: sandbox/datalab/AUDIT.md :: "Что за данные"
  - contains: sandbox/datalab/AUDIT.md :: "Находки"
  - contains: sandbox/datalab/AUDIT.md :: "Вопросы"
  - manual: "Ученик называет три проблемы из аудита и объясняет, какому выводу по этим данным нельзя верить, пока проблемы не сняты"
PASS_THRESHOLD: 70
