# Финальный проект — Скринер резюме + бот онбординга

ROLE: hr
GOAL: Ученик проходит полный цикл на своём материале: план → сборка → git → демо — и получает два переиспользуемых инструмента: скринер резюме (страница: вставил резюме — получил таблицу по критериям и вердикт-подсказку) и бот онбординга (локальная чат-страница, отвечающая новичку по FAQ).
WHY: Всё, что было до этого, — разовые разборы: скрининг руками агента, письма под конкретную вакансию. Разница между «я умею попросить агента» и «я собрал инструмент» — в том, что инструментом пользуется вся команда без тебя: скринером — коллеги-рекрутеры под свои вакансии, ботом — каждый новый сотрудник. Это и есть выпускная работа трека: из HR, который делает руками, — в HR, у которого работают инструменты.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Начни с рамки: «у тебя в sandbox/hr уже есть все детали — профиль, тестовые резюме, FAQ; сегодня собираем из них два инструмента». Спроси, какой хочет собрать первым; если сомневается — советуй скринер: он короче и разгоняет.
- Скажи оценку времени: 90–120 минут. Честно предупреди: это самая длинная работа курса, удобно делать в два подхода — скринер отдельно, бот отдельно; git сохранит прогресс между подходами.
- Держи рамку самодостаточности: оба инструмента — локальные страницы, работают офлайн, без ключей и внешних сервисов. Самый надёжный вариант — обычные HTML-страницы, которые открываются из файла; технику пусть выбирает агент, ученик ставит требования.
- Веди циклом из _core (план → шаг → проверка шага), по одному микро-шагу:
  1. **План.** Пусть попросит агента: «составь план в sandbox/hr/tools/PLAN.md: 3–5 шагов, каждый заканчивается чем-то проверяемым; сначала скринер, потом бот; пока не пиши код». Пусть прочитает и поправит словами — это его главная точка контроля (атом core `01-plan-then-build.md`).
  2. **Скринер.** Требования ученик формулирует сам, состав подскажи: страница `sandbox/hr/tools/screener/index.html`; критерии из profile.md запечены в страницу и редактируемы прямо на ней; поле, куда вставляется текст резюме; на выходе — таблица «критерий → найдено/не найдено/непонятно» и вердикт-ПОДСКАЗКА; на видном месте — надпись, что это фильтр первого прохода и решение принимает человек. Проверка: пусть откроет страницу и прогонит 2–3 тестовых резюме из screening/resumes/ — сильное и слабое различаются? Стоп-сигнал ловится? Не различаются — правки конкретными замечаниями.
  3. **Коммит.** Скринер работает → «закоммить с понятным сообщением». Потом бот — отдельными коммитами (атом core `04-git-hygiene.md`).
  4. **Бот онбординга.** Страница `sandbox/hr/tools/onboarding-bot/index.html`: окно чата; новичок пишет вопрос — бот находит подходящие ответы в запечённом faq.md (поиск по словам — этого достаточно, никакого ИИ внутри страницы не нужно); ничего не нашёл — честно отвечает «не знаю, спроси у …» с контактом из FAQ, а НЕ выдумывает. Проверка: три вопроса из FAQ своими словами (не дословно!) + один вопрос, которого в FAQ нет, — бот должен честно не знать.
  5. **Демо и (по желанию) публикация.** Пусть прогонит демо целиком, как показывал бы команде. Есть интернет и желание — «опубликуй самым простым бесплатным способом» (как в _core m02; логинится ученик сам, агент не вводит пароли), ссылку — в `sandbox/hr/tools/DEPLOY.md`. Без интернета — «локально» в DEPLOY.md, это не провал. Напомни про данные: публиковать можно только с тестовыми резюме и FAQ без персоналий.
- Точки помощи: хочет всё и сразу («и почту, и hh, и телеграм») → в план первой версии только ядро, хотелки — списком в конец PLAN.md; бот отвечает не тем ответом → чини данные, не код: переформулируй вопрос в faq.md, добавь синонимы («зарплата» и «оклад»), пересобери; скринер на всё говорит «не найдено» → разбери на одном резюме, каким словам в тексте должен соответствовать критерий, и попроси агента искать по вариантам формулировок; что-то сломалось после правки → ошибка целиком агенту + «почини причину, не заглушай» (атом core `03-debug-with-agent.md`), совсем плохо — откат к последнему коммиту; две правки одного места не помогли → новый заход с уточнённой формулировкой (атом core `02-iterate.md`).
- Назови типичное заблуждение вслух: «настоящий инструмент — это когда сложно и с сервером» — нет: настоящий инструмент это когда им пользуются. Страница, которую коллега открыл и она решила его задачу, — более настоящая, чем недостроенная «платформа».
- В конце — вызови проверку и, если passed, поздравь конкретно и без пафоса: перечисли, что он собрал за трек — профиль, скрининг, письма, база онбординга и два живых инструмента — и что цикл «план → сборка → git → демо» теперь его рабочий навык. Скажи честно про следующий шаг: инструменты сейчас на тестовых данных; чтобы пустить в работу — прогнать с обезличенными реальными данными и показать команде.

## Ученику (живой сценарий)

«Представь: ты показал(а) менеджеру разбор откликов и welcome-страницу. Реакция предсказуемая: "Слушай, а сделай так, чтобы это работало у всех рекрутеров. И чтобы новички не тебе писали, а куда-нибудь ещё". Поздравляю — тебе только что заказали два внутренних продукта. Все детали у тебя уже есть: профиль, резюме, FAQ. Осталось собрать.» (~90–120 минут, можно в два подхода)

Что делаем руками:

1. Попроси агента составить план в `sandbox/hr/tools/PLAN.md`: 3–5 шагов, каждый — с проверяемым результатом, сначала скринер, потом бот, код пока не писать. Прочитай и поправь — дальше агент работает по твоему плану.
2. Собери скринер: страница `sandbox/hr/tools/screener/index.html` — твои критерии из profile.md (редактируемые прямо на странице), поле для текста резюме, на выходе таблица по критериям и вердикт-подсказка с честной припиской «решение принимает человек». Прогони 2–3 тестовых резюме: сильное и слабое должны различаться. Работает — коммит.
3. Собери бота: страница `sandbox/hr/tools/onboarding-bot/index.html` — чат, который отвечает на вопросы новичка по твоему faq.md, а на неизвестное честно говорит «не знаю, спроси у …». Задай три вопроса своими словами и один, которого в FAQ нет. Работает — коммит.
4. Прогони демо целиком, как показывал(а) бы команде. Хочешь — опубликуй самым простым бесплатным способом и запиши ссылку в `sandbox/hr/tools/DEPLOY.md` (только тестовые данные!); работаешь офлайн — напиши в DEPLOY.md «локально».

В понедельник ты показываешь не разбор, а инструменты. Разбор устаревает к среде — инструменты остаются.

## Артефакт

Папка `sandbox/hr/tools/` с: `PLAN.md` (план из проверяемых шагов), `screener/index.html` (скринер: редактируемые критерии, вставка резюме, таблица соответствия, вердикт-подсказка, приписка про решение человека), `onboarding-bot/index.html` (чат по FAQ с честным «не знаю»), `DEPLOY.md` (ссылка или «локально»). Git-история `sandbox/hr` — минимум 3 коммита.
