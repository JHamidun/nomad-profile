# Миссия 5 — Финальный проект: продукт под ключ

ROLE: founder
GOAL: Ученик собирает из наработок трека цельный продукт под ведением агента: лендинг с оффером и тарифами + бот-приёмщик заявок + подготовленный приём оплаты — в одном репозитории, с git-историей и (при желании) публичной ссылкой.
WHY: Кусочки уже есть: оффер, лендинг, экономика, бот, тарифы. Продукт — это когда они связаны в один путь клиента: увидел страницу → понял оффер → выбрал тариф → оставил заявку → получил ответ, куда платить. Такой путь показывают инвестору, по нему запускают первые продажи — и это финальная витрина всего, чему ученик научился на курсе.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Начни с вопроса: под какое событие собираем — демо-день, созвон с инвестором, запуск продаж? Дедлайн делает сборку настоящей.
- Скажи оценку времени: 90–120 минут. Предложи два подхода: сборка + git отдельно, деплой и онлайн-шаги — отдельным заходом; прогресс сохранится.
- Веди по циклу «план → результат → git → деплой» (тот же скелет, что в миссии 2 фундамента, — ученик его уже проходил, напомни об этом: сейчас меняется только начинка):
  1. **План.** Пусть попросит агента: «составь план в `sandbox/founder/product/PLAN.md`: 4–6 шагов, каждый заканчивается чем-то проверяемым; пока не пиши код». Пусть прочитает и поправит словами — это его точка контроля.
  2. **Сборка по шагам.** Единый `index.html`: оффер из миссии 1 + блок тарифов из миссии 4, кнопки ведут на заявку/бота — один путь клиента без тупиков. Бот из миссии 3 переезжает в `product/bot/` — и dry-run обязан работать на новом месте. `PAYMENTS.md` из миссии 4 актуализируется под финальные тарифы. По шагу за раз: «делай шаг 1» → посмотрел → «делай шаг 2».
  3. **Git.** Репозиторий в `product/`, коммит после каждого осмысленного шага (минимум 3), история читается: пусть попросит показать `git log` и увидит свои точки возврата.
  4. **Деплой.** Если есть интернет: «опубликуй лендинг самым простым бесплатным способом» — GitHub Pages, Netlify или Vercel; логинится ученик сам. Ссылку — в `DEPLOY.md`, открыть с телефона. Без интернета — честная пометка «локально» в `DEPLOY.md`, это полноценный зачёт.
  5. **Онлайн-шаги по желанию** (если есть время, аккаунты и настроение): живой Telegram-бот — создать бота у BotFather и попросить агента подключить логику из `bot.js`; токен НЕ в git — в `.env` (атом `core/04-git-hygiene.md`). Реальная платёжная ссылка провайдера — в кнопку «Купить» по плану из `PAYMENTS.md`. Не дави: офлайн-версия со всеми заглушками — законченный продукт под ключ.
- Точки помощи: scope creep («ещё блог, личный кабинет и партнёрку») → рамка MVP: один оффер, один-три тарифа, один сценарий бота, остальное — после курса; при переносе бота падает dry-run → скорее всего пути к файлам, ошибку целиком агенту; страх «сломаю то, что уже работало» → git уже есть, откат дешёвый: «покажи, что изменилось», «откати к последнему коммиту»; деплой просит логин и подтверждение почты → нормально, разовая настройка минут на 10–15.
- Назови типичное заблуждение вслух: «MVP — это урезанный стыдный продукт» — MVP это полный путь клиента при минимуме содержимого: путь есть весь, содержимого — ровно сколько нужно для первой продажи.
- В конце — вызови проверку и, если passed, скажи прямо: трек пройден, у него в руках продукт, который можно показывать клиентам и инвестору. И что дальше цикл тот же — спрос → экономика → продукт → деньги, — только вещи будут крупнее. Отметь в state завершение трека.

## Ученику (живой сценарий)

«Представь: в следующую пятницу — демо-день. Или первый созвон с инвестором. Или ты просто решил(а), что хватит готовиться — пора продавать. Нужен не набор файлов по папкам, а продукт: страница, которая продаёт, бот, который принимает заявки, и внятный ответ на "куда платить". Всё уже есть в кусках — собираем под ключ.» (~90–120 минут, можно в два подхода)

Что делаем руками:

1. Попроси агента составить план в `sandbox/founder/product/PLAN.md`: 4–6 проверяемых шагов, без кода. Прочитай, поправь словами.
2. Собирай по шагам: единый лендинг (оффер + тарифы + кнопки к заявке/боту), бот переезжает в `product/bot/` (проверь dry-run на новом месте!), `PAYMENTS.md` — под финальные тарифы.
3. Застрахуйся: git-репозиторий в `product/`, коммит после каждого шага. Попроси показать историю — вот твои точки возврата.
4. Опубликуй лендинг бесплатным способом и запиши ссылку в `DEPLOY.md` (или честно «локально» — тоже зачёт). Открой с телефона: так его увидит клиент.
5. Есть силы и аккаунты — включи бой: живой Telegram-бот через BotFather (токен в `.env`, не в git) и платёжная ссылка в кнопку «Купить» по своему плану из `PAYMENTS.md`.
6. Финальный прогон: пройди путь клиента сам, от заголовка до «куда платить». Каждый разрыв пути — правка агенту.

В пятницу ты показываешь продукт, а не презентацию о нём.

## Артефакт

Папка `sandbox/founder/product/` с: `PLAN.md`, `index.html` (оффер + тарифы + CTA), `bot/` (scenario.md, bot.js, dry-run.js), `PAYMENTS.md`, `DEPLOY.md` (ссылка или «локально») и git-историей минимум из 3 коммитов.
