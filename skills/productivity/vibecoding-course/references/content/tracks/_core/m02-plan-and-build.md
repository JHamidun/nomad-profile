# Миссия 2 — План → результат → git → деплой

ROLE: CORE
GOAL: Ученик проходит полный цикл вайбкодинга: план из проверяемых шагов → работающая вещь → история изменений в git → опубликованная ссылка (или локальный показ, если без интернета).
WHY: Это скелет любой реальной задачи: без плана агент решает не ту задачу, без git страшно менять и нечем откатить, без деплоя результат нельзя показать никому, кроме себя. Освоил цикл один раз — дальше меняется только начинка: лендинг, прототип, калькулятор, отчёт.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Открой `sandbox/about-me.md` и начни с поля «Хочу собрать»: проект этой миссии — его вещь, не учебная. Если задумка тянет на неделю работы → вместе ужмите до одностраничной версии, которую реально собрать за сессию (первая работающая версия, не финал). Если поле пустое или устарело — спроси заново.
- Скажи оценку времени: 60–90 минут. Это самая длинная миссия фундамента — предупреди, что можно сделать в два подхода (git и деплой — отдельным заходом; прогресс сохранится).
- Веди циклом из четырёх тактов (атом `01-plan-then-build.md` — пересказывай точечно):
  1. **План.** Пусть попросит агента: «составь план в `sandbox/project/PLAN.md`: 3–5 шагов (озаглавь каждый «Шаг N»), каждый шаг заканчивается чем-то проверяемым; пока не пиши код». Пусть прочитает план глазами и поправит словами — это его главная точка контроля. (В Claude Code есть Plan Mode, можешь упомянуть, но достаточно просьбы «сначала план, без кода».)
  2. **Сборка по шагу.** «Делай шаг 1» → посмотрел результат → «делай шаг 2». Не позволяй просить «сделай всё сразу».
  3. **Git.** После первого работающего состояния: пусть попросит «сделай из sandbox/project git-репозиторий и закоммить с понятным сообщением». После следующего изменения — второй коммит. Потом пусть попросит показать историю (агент выполнит `git log --oneline`) и увидит свои точки возврата.
  4. **Деплой.** Если есть интернет: «опубликуй страницу, предложи самый простой бесплатный вариант» — GitHub Pages, Netlify или Vercel; логинится ученик сам, агент не вводит пароли. Ссылку — в `sandbox/project/DEPLOY.md`, и пусть откроет её (лучше с телефона). Если интернета или желания регистрироваться нет — это НЕ провал: в `DEPLOY.md` пишем «локально» и каким файлом открывать; порог проверки это учитывает.
- Точки помощи: план из 15 шагов → ужать до 5; git ругается на имя/почту (unknown identity) → пусть покажет ошибку агенту, тот настроит git config; страх «сейчас всё сломаю» → покажи откат: «покажи, что изменилось» / «откати к последнему коммиту», в Claude Code есть и /rewind; деплой просит логин/подтверждение почты → нормально, это разовая настройка минут на 10–15; в проекте появился ключ API → секреты не коммитим, пусть попросит агента настроить .env и .gitignore (атом `04-git-hygiene.md`).
- Назови типичное заблуждение вслух: «деплой — это для программистов» — статичная страница публикуется за минуты, а страшно только в первый раз (атом `05-deploy.md`).
- В конце — вызови проверку и, если passed, похвали конкретно: у него в руках полный цикл — план, работающая вещь, история изменений и ссылка. Это и есть вайбкодинг, остальное — наращивание мяса. Открой трек его роли.

## Ученику (живой сценарий)

«Представь: пятница. В понедельник — планёрка, и ты сказал(а), что покажешь работающий инструмент, а не слайды про него. Та самая вещь из твоего about-me — время её собрать. Не финальную версию — первую работающую.» (~60–90 минут, можно в два подхода)

Что делаем руками:

1. Попроси агента составить план в `sandbox/project/PLAN.md`: 3–5 шагов, каждый заканчивается чем-то проверяемым, код пока не писать. Прочитай план. Не согласен(на) — правь словами, это дёшево.
2. Иди по плану: «делай шаг 1» → посмотри → «делай шаг 2». К концу у тебя открывается `sandbox/project/index.html` с первой работающей версией.
3. Застрахуйся: попроси агента завести git-репозиторий в `sandbox/project` и закоммитить. Внеси ещё одно изменение — второй коммит. Попроси показать историю: вот твои точки возврата.
4. Опубликуй: попроси агента выложить страницу в интернет самым простым бесплатным способом (регистрируешься и логинишься ты, это займёт минут 10–15 в первый раз). Ссылку запиши в `sandbox/project/DEPLOY.md` и открой её с телефона. Без интернета — запиши в `DEPLOY.md` «локально» и покажи страницу из файла.

В понедельник ты показываешь ссылку, а не обещания.

## Артефакт

Папка `sandbox/project/` с: `PLAN.md` (план из проверяемых шагов), `index.html` (работающая первая версия твоей вещи), git-историей минимум из 2 коммитов и `DEPLOY.md` (публичная ссылка — или пометка «локально»).
