# Миссия 1 — Один источник правды

ROLE: project
GOAL: Ученик умеет превращать хаос задач своего проекта (чаты, таблицы, голова) в структурированный реестр `tasks.json` со схемой полей и написанными правилами статусов.
WHY: Самый частый режим работы проджекта — «сборщик статуса вручную»: руководитель спрашивает «что по проекту?», и начинается археология по трём чатам и двум таблицам. Реестр — это фундамент всего трека: на него встанут доска (миссия 2), авто-отчёт (миссия 3) и мост к трекеру команды (миссия 4). Нет единого источника правды — нечего автоматизировать.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Сначала спроси: какой проект у него сейчас в работе и где живут задачи по нему (Jira? Trello? Excel? чаты? голова?). Весь трек строим на ЭТОМ проекте — не на учебном. Если активного проекта нет — пусть возьмёт ближайший прошлый или личный (ремонт, переезд, запуск курса — годится всё, где есть задачи, сроки и люди).
- Скажи оценку времени: 30–45 минут.
- Дай сделать РУКАМИ, по одному микро-шагу:
  1. **Вывалить как есть.** Пусть создаст `sandbox/pm/tracker/raw.md` (сам или попросив агента) и накидает туда 8–15 задач проекта в свободной форме — как помнит, как в чатах писали: «Лёша обещал макеты к среде», «согласовать бюджет — висит на финдире». Без формата, это черновик.
  2. **Согласовать схему.** Пусть спросит агента: «какие поля нужны в реестре задач, чтобы потом собирать доску и отчёты?» — и вместе остановятся на минимуме: `id`, `title`, `owner`, `due`, `status`, `note`. Ключи — латиницей (по ним потом будут работать доска и отчёт), значения — на русском. Статусы зафиксировать набором: `todo` / `doing` / `done` / `blocked`.
  3. **Структурировать.** Пусть попросит агента превратить `raw.md` в `sandbox/pm/tracker/tasks.json` по схеме — и, где данных не хватает (нет срока, нет ответственного), пусть агент СПРАШИВАЕТ, а не выдумывает. Отвечает ученик — это его проект, он источник правды, агент только руки.
  4. **Написать правила статусов.** Пусть попросит агента создать `sandbox/pm/tracker/STATUS-RULES.md` и продиктует своими словами: что означает каждый статус (когда задача честно `doing`, а когда это `blocked`) и правило «красной» задачи (например: просрочен `due` или статус `blocked` дольше двух дней). Это не формальность — по этому правилу в миссии 3 будет считаться светофор отчёта.
- Точки помощи: задач набралось меньше 8 → пусть добавит смежные и «висящие» (то, что стыдно вспоминать, — самое ценное для реестра); хочет Excel вместо JSON → объясни без снобизма: JSON — просто текстовый файл, агент читает и правит его сам, а в миссии 2 из него соберётся доска; CSV тоже вариант, но JSON надёжнее для вложенных заметок; пугают английские ключи → значения остаются русскими, ключи — это «имена колонок», их никто не читает вслух; агент придумал сроки, которых ученик не называл → поймать за руку и попросить пометить как `null` или спросить — фабрикация данных в реестре хуже пустого поля.
- Назови типичное заблуждение вслух: «реестр — это бюрократия, у нас всё в чате». Чат — это лента событий, а не состояние проекта: статус в нём приходится собирать заново при каждом вопросе. Реестр собирается один раз и дальше только обновляется (атом `.course/knowledge/project/00-single-source-of-truth.md`, перескажи в двух предложениях).
- В конце — вызови проверку (скилл course-check) и, если passed, похвали конкретно: у него впервые есть файл, по которому на вопрос «что по проекту?» можно ответить за десять секунд. Открой миссию 2 — из этого файла соберём доску.

## Ученику (живой сценарий)

«Представь: воскресенье вечером прилетает от руководителя — "завтра в 9:30 у меня встреча с заказчиком, скинь картину по проекту". Задачи у тебя в двух чатах, одной таблице и частично в голове. Сегодня собираем их в одно место — в последний раз вручную.» (~30–45 минут)

Что делаем руками:

1. Создай `sandbox/pm/tracker/raw.md` и вывали туда 8–15 задач своего реального проекта как есть — обрывками, как в чатах. Не причёсывай.
2. Спроси агента, какие поля нужны реестру задач, чтобы потом собирать из него доску и отчёты. Согласуйте минимум: `id`, `title`, `owner`, `due`, `status`, `note` — и четыре статуса: `todo` / `doing` / `done` / `blocked`.
3. Попроси агента превратить `raw.md` в `sandbox/pm/tracker/tasks.json` по этой схеме. Где данных не хватает — он должен спросить тебя, а не сочинить. Отвечай честно: «срока нет» — это тоже данные.
4. Продиктуй агенту правила в `sandbox/pm/tracker/STATUS-RULES.md`: что значит каждый статус и когда задача считается «красной» в твоём проекте.

К концу у тебя есть единый источник правды — и завтра ты отвечаешь на «что по проекту?» по одному файлу, а не по трём чатам.

## Артефакт

Папка `sandbox/pm/tracker/` с: `raw.md` (задачи как были), `tasks.json` (8–15 задач по схеме id/title/owner/due/status/note) и `STATUS-RULES.md` (значения статусов + правило «красной» задачи).
