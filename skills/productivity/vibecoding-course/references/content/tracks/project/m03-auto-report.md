# Миссия 3 — Отчёт, который собирает себя

ROLE: project
GOAL: Ученик умеет согласовать шаблон статус-отчёта (светофор, сделано, риски, «нужно от вас») и получать готовый `report.md` из `tasks.json` — без часа ручного письма в пятницу вечером.
WHY: Еженедельный статус заказчику или руководству — самая предсказуемая рутина проджекта: каждый раз одна и та же структура, меняются только данные. И именно её чаще всего делают вручную — час на «вспомнить, что сделано, и красиво сформулировать». Когда отчёт собирается из реестра, этот час превращается в минуту, а отчёт перестаёт зависеть от памяти и настроения в пятницу в 17:30.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Сначала спроси: кому он отчитывается по проекту, как часто и в каком виде (письмо? сообщение? слайд?). И второй вопрос: сколько времени уходит на один такой отчёт. Эта цифра — ставка миссии, назови её вслух.
- Скажи оценку времени: 40–60 минут.
- Дай сделать РУКАМИ:
  1. **Шаблон.** Пусть попросит агента создать `sandbox/pm/report/TEMPLATE.md` и вместе наполнят структуру: Светофор проекта (зелёный/жёлтый/красный + одна фраза почему), Сделано за период, В работе, Риски и блокеры, Нужно от заказчика/руководителя. В шаблоне обязательно зафиксировать ПРАВИЛО светофора со ссылкой на `STATUS-RULES.md` из миссии 1: например, «есть красные задачи → красный; есть blocked или просрочка → жёлтый; иначе зелёный». Светофор считается из данных, не выбирается по настроению.
  2. **Сборка.** Пусть попросит агента собрать `sandbox/pm/report/report.md` строго из `sandbox/pm/tracker/tasks.json` по шаблону. Жёсткое условие в запросе: ничего не выдумывать; если данных для раздела нет — писать «нет данных», а не сочинять достижения.
  3. **Прочитать глазами заказчика.** Пусть прочитает отчёт как человек, который платит за проект: где расплывчато? где отчёт приукрашивает? Типовая проверка: светофор совпадает с правилом? формулировки — факты («закрыто 4 задачи из 12, две просрочены») или вода («работа идёт по плану»)? Правки — агенту, конкретными фразами.
  4. **Прогнать пересборку.** Пусть поменяет статус задачи в `tasks.json` (или срок — чтобы появилась просрочка) и попросит «пересобери отчёт». Светофор и разделы должны измениться сами — это момент, ради которого всё затевалось.
  5. **По желанию — скрипт.** Если на машине есть Python или Node (пусть спросит агента — тот сам проверит), можно попросить написать скрипт, который пересобирает отчёт одной командой без участия агента. Нет — не страшно: «пересобери отчёт по шаблону» агенту — это уже автоматизация его пятничного часа.
- Точки помощи: отчёт раздулся на три страницы → у получателя 30 секунд, ужать до одного экрана, детали живут на доске; светофор упорно зелёный при просроченных задачах → проверить правило в TEMPLATE.md и попросить агента показать, КАК он посчитал светофор; агент пишет «значительный прогресс по ключевым направлениям» → поймать: только факты и числа из tasks.json; в отчёт попали задачи, которых нет в реестре → тот же рефлекс, что в миссии 2: данные — только из файла.
- Назови типичное заблуждение вслух: «отчёт — это текст, который надо писать». Отчёт — это представление данных, как доска, только словами. Руками в нём остаются две вещи: вывод («что это значит для проекта») и просьба («что нужно от вас») — их пусть допишет сам, это как раз работа проджекта (атом `.course/knowledge/project/01-status-report.md`).
- В конце — вызови проверку и, если passed, похвали конкретно: назови его цифру из начала («ты говорил — час каждую пятницу») и покажи, что теперь это минута плюс два предложения выводов. Открой миссию 4 — подружим контур с трекером команды.

## Ученику (живой сценарий)

«Представь: пятница, 17:30. Заказчик ждёт статус письмом до конца дня. Обычно это час: поднять чаты, вспомнить, что сделано, сформулировать так, чтобы не звучало тревожно. Сегодня — последний раз, когда этот час существует.» (~40–60 минут)

Что делаем руками:

1. Согласуй с агентом шаблон `sandbox/pm/report/TEMPLATE.md`: Светофор (с правилом — из каких данных он считается), Сделано, В работе, Риски и блокеры, Нужно от заказчика. Правило светофора привяжи к своим `STATUS-RULES.md` — не к настроению.
2. Попроси агента собрать `sandbox/pm/report/report.md` строго из `tasks.json` по шаблону. Скажи прямо: ничего не выдумывать, нет данных — писать «нет данных».
3. Прочитай отчёт глазами заказчика. Где вода — потребуй факты и числа. Где приукрашено — верни к правилу светофора.
4. Проверь механику: поменяй статус задачи в `tasks.json`, попроси пересобрать отчёт — светофор и разделы должны обновиться сами.
5. Допиши руками две строки, которые не соберёт ни один скрипт: твой вывод и твоя просьба к получателю.

К концу у тебя есть отчёт, который собирается из данных за минуту, — и пятничный час, который снова твой.

## Артефакт

Папка `sandbox/pm/report/` с: `TEMPLATE.md` (структура отчёта + правило светофора) и `report.md` (отчёт, собранный из `tasks.json`: светофор, сделано, в работе, риски, «нужно от вас»).
