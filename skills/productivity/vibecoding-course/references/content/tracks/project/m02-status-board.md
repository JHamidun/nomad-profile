# Миссия 2 — Доска для планёрки

ROLE: project
GOAL: Ученик умеет собирать из `tasks.json` визуальную доску статусов `board.html` — колонки по статусам, просрочки подсвечены — и пересобирать её за минуту, когда данные изменились.
WHY: Планёрка, где статус собирают устно по кругу, съедает по 15 минут на «а что с той задачей?». Доска на экране переворачивает разговор: вместо «расскажите, кто что делает» — «вот картина, обсуждаем красное». Это первая вещь в треке, которую ученик реально выводит на проектор — и первый раз, когда его реестр из миссии 1 начинает работать на него.

## Наставнику (как вести — читает Claude Code)

- НЕ лекция. Сначала спроси: как сейчас проходит его планёрка (или статус-созвон) и что на ней хочется видеть на одном экране. Ответ — это и есть бриф доски; навык брифа у него уже есть из миссии 1 фундамента.
- Скажи оценку времени: 40–60 минут.
- Дай сделать РУКАМИ:
  1. **Бриф доски.** Пусть сформулирует агенту: собери `sandbox/pm/tracker/board.html` из `sandbox/pm/tracker/tasks.json` — четыре колонки по статусам (`todo` / `doing` / `done` / `blocked`) — показывай все четыре всегда, даже пустые; в карточке название, ответственный и срок; просроченные (по правилу из `STATUS-RULES.md`) подсвечены; наверху счётчики задач по колонкам и дата сборки. И ключевое требование: данные встроить ВНУТРЬ файла, чтобы доска открывалась двойным кликом, без сервера и интернета.
  2. **Открыть и сверить.** Пусть откроет `board.html` в браузере и сверит с `tasks.json`: все ли задачи на месте, в тех ли колонках, там ли подсветка. Агент мог что-то потерять — сверка глазами обязательна.
  3. **Прогнать обновление.** Пусть попросит агента поменять статус одной реальной задачи в `tasks.json` (например, `doing` → `done`) и пересобрать доску. Обновил страницу — карточка переехала. Это и есть рабочий цикл: правишь данные → просишь «обнови доску» → показываешь.
  4. **Две-три итерации под свою планёрку.** Что реально нужно его команде: блокеры первой колонкой? фильтр по ответственному? крупнее шрифт для проектора? Правки — конкретными фразами, по одной-две за раз (атом `.course/knowledge/core/02-iterate.md`).
- Точки помощи: доска открылась ПУСТАЯ или белая → самый частый затык: страница пытается читать `tasks.json` отдельным запросом, а браузер запрещает локальным файлам читать соседние файлы — пусть скажет агенту «доска пустая при открытии файла с диска», тот встроит данные прямо в html при сборке; доска пёстрая, как ёлка → верни к назначению: это экран для планёрки, сигнальных цветов достаточно двух (красный — просрочка/блок, всё остальное спокойное); на доске задача, которой нет в `tasks.json` → агент нафантазировал, попросить брать данные только из файла и пересобрать; дата в карточках в странном формате → попросить формат «5 июля» или «05.07» — как привычно команде.
- Назови типичное заблуждение вслух: «для доски нужен Jira или сервер». Нет: доска — это представление твоих данных; статичный html из `tasks.json` закрывает планёрку целиком. Сервер нужен, когда команда должна двигать карточки сама, — и это уже другая задача с другой ценой.
- В конце — вызови проверку и, если passed, похвали конкретно: он только что прошёл цепочку «данные → представление» — ту же, на которой стоят все дашборды мира, только эта собрана под его планёрку за вечер. Открой миссию 3 — по той же цепочке соберём отчёт.

## Ученику (живой сценарий)

«Представь: понедельник, 10:00, планёрка. Обычно первые 15 минут уходят на "так, а что у нас по дизайну… а бэкенд где…". Сегодня ты открываешь один файл, выводишь на экран — и команда видит всю картину: четыре колонки, красным — то, что горит. Разговор сразу начинается с главного.» (~40–60 минут)

Что делаем руками:

1. Попроси агента собрать `sandbox/pm/tracker/board.html` из твоего `tasks.json`: колонки по статусам, в карточке — название, ответственный, срок; просроченные — красным (правило просрочки у тебя уже написано в `STATUS-RULES.md`); сверху — счётчики и дата сборки. Обязательно скажи: данные встроить внутрь файла, чтобы доска открывалась двойным кликом без сервера.
2. Открой доску в браузере. Сверь с `tasks.json` глазами: все задачи на месте? в тех колонках? красное — там, где должно быть?
3. Поменяй статус одной задачи (попроси агента поправить `tasks.json`) и скажи «пересобери доску». Обнови страницу — карточка переехала. Запомни этот цикл, он теперь твой.
4. Догони доску до своей планёрки: одна-две конкретные правки за раз — «блокеры первой колонкой», «шрифт крупнее, будет на проекторе».

К концу у тебя есть доска, которую не стыдно вывести на экран, — и минутный способ держать её свежей.

## Артефакт

`sandbox/pm/tracker/board.html` — доска статусов, собранная из `tasks.json`: открывается в браузере двойным кликом (без сервера), колонки по статусам, просрочки подсвечены, данные совпадают с реестром.
