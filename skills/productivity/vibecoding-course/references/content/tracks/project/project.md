# Миссия 5 — Финальный проект: свой контур управления проектом

ROLE: project
GOAL: Ученик самостоятельно, полным циклом из фундамента (план → сборка по шагам → git → опционально деплой), собирает под свой реальный проект собственный контур: реестр задач со своей схемой, доску под свою планёрку, авто-отчёт по своему шаблону и минимум один мост к внешнему инструменту — плюс README, по которому он сам через месяц всё пересоберёт.
WHY: Миссии 1–4 были тренажёром: маршрут задан, схема подсказана, затыки предугаданы. В работе так не будет — будет новый проект, свои особенности («у нас две команды и два трекера», «заказчику нужен отчёт на английском») и никого, кто заранее написал план. Финальный проект — это проверка, что ученик умеет пройти путь сам: спланировать, собрать, не потерять по дороге git и оставить инструкцию. То, что получится, — не учебная поделка, а инструмент, с которым он выходит на ближайшую планёрку.

## Наставнику (как вести — читает Claude Code)

- Твоя роль меняется: не ведущий, а ревьюер. Ученик планирует и рулит сам, ты — точки помощи и честная обратная связь по плану. Не подсказывай наперёд то, о чём не спросили.
- Сначала спроси: под какой проект собираем боевой контур. Лучший вариант — тот же проект, что в миссиях 1–4 (данные уже есть), но «начисто» и под реальные требования: его поля, его статусы, его шаблон отчёта, его получатели. Если хочет взять другой проект — отлично, это даже честнее как экзамен.
- Скажи оценку времени: 90–120 минут, можно в два подхода (например, план + реестр + доска в первый, отчёт + мост + README во второй; git с первого коммита, прогресс не потеряется).
- Рамка (объяви один раз, дальше пусть идёт сам):
  1. **План до сборки.** `sandbox/pm/final/PLAN.md`: 4–6 шагов (озаглавь каждый «Шаг N»), каждый заканчивается чем-то проверяемым. Пусть попросит агента составить черновик плана и поправит его СЛОВАМИ до начала сборки — как в миссии 2 фундамента. План без шага про git или README — повод спросить «а как ты вернёшься к этому через месяц?».
  2. **Состав минимум:** реестр с ≥10 реальными задачами (схему полей и статусы решает сам — может отличаться от учебной); `board.html` под его планёрку; `TEMPLATE.md` + собранный `report.md` + версия для чата; минимум один мост — импорт экспорта из трекера команды ИЛИ экспорт наружу (сообщение для чата — уже мост; календарь дедлайнов или письмо — тоже); git с ≥3 коммитами по ходу, не одним в конце; `README.md` — инструкция самому себе: как обновить данные, пересобрать доску и отчёт, прогнать импорт (какими просьбами агенту или каким скриптом).
  3. **Деплой — опционально и с головой.** Если хочет публичную ссылку на доску — только если данные не чувствительны или обезличены: реальные фамилии и задачи заказчика в публичный интернет не выкладываем. Сомневается — пусть спросит себя «показал бы я это на собеседовании конкуренту?». Без деплоя проект полноценен.
- Точки помощи (только когда застрял, не наперёд): план на 12 шагов → ужать до 4–6, детали уйдут внутрь шагов; захотел «всё по-новому» и застрял на схеме → напомни: куски из миссий 1–4 можно переиспользовать, экзамен не на память, а на цикл; собрал всё, но README из одной строки → тест README: «закрой сессию, открой новую, пересобери отчёт только по README» — если не получилось, README не готов; забыл про git и вспомнил в конце → лучше поздний первый коммит, чем никакого, но назови вслух: страховка работает, только если её включили до аварии.
- Если что-то сломалось по дороге — это материал: ошибка целиком агенту, разбор причины, атом `.course/knowledge/core/03-debug-with-agent.md`.
- В конце — вызови проверку. Если passed: похвали конкретно, по-крупному — он пришёл с задачами в трёх чатах, а уходит с контуром, где данные сами становятся доской, отчётом и сообщением в чат; и он собрал это сам, по собственному плану. Скажи прямо: трек закрыт, дальше — вести этим контуром живой проект и наращивать под себя (напоминания о просрочках, отчёт на двух языках, экспорт для стейкхолдеров — теперь он знает, как просить).

## Ученику (живой сценарий)

«Представь: в понедельник у тебя стартует новый проект — или ты решил, что действующий больше не будет жить в трёх чатах. Никакого учебного маршрута: есть агент, есть твой опыт из четырёх миссий и есть два часа. Собери себе боевой контур: реестр → доска → отчёт → мост. Так, как нужно ТВОЕМУ проекту.» (~90–120 минут, можно в два подхода)

Рамка — а внутри неё рулишь ты:

1. Начни с плана: попроси агента составить `sandbox/pm/final/PLAN.md` на 4–6 проверяемых шагов, поправь его словами до первой строчки кода. Подумай, чем твой контур отличается от учебного: другие поля? другие статусы? отчёт на английском? два получателя с разными шаблонами?
2. Иди по плану шаг за шагом. После первого работающего куска — git-репозиторий в `sandbox/pm/final` и первый коммит; дальше коммить по ходу, минимум три.
3. Собери состав: реестр с десятью и больше реальными задачами, доска под твою планёрку, шаблон и собранный отчёт, версия для чата — и хотя бы один мост во внешний мир (импорт выгрузки команды или экспорт наружу).
4. Напиши `README.md` для себя-через-месяц: как обновить данные, как пересобрать доску и отчёт, как прогнать импорт. Проверь его честно: по README, не по памяти.
5. Хочешь — опубликуй доску (только без чувствительных данных). Не хочешь — просто выведи её на ближайшей планёрке. Это и есть сдача проекта.

К концу у тебя не «результат курса», а инструмент, которым ты работаешь со следующего понедельника.

## Артефакт

Папка `sandbox/pm/final/` с: `PLAN.md` (план из проверяемых шагов, написанный до сборки), реестром задач (≥10 реальных задач), `board.html`, `TEMPLATE.md` + `report.md` + версией отчёта для чата, минимум одним мостом (папка/файл импорта или экспорта), git-историей минимум из 3 коммитов и `README.md` — инструкцией, как всем этим пользоваться.
