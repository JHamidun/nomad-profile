# Git-гигиена: страховка, которая делает смелым

> Атом базы знаний курса.

Git — это машина времени для твоего проекта. Каждый коммит — сохранённая точка, к которой можно вернуться. Для вайбкодера git важнее, чем для классического программиста: агент меняет файлы быстро и помногу, и без сохранённых точек любое «а давай попробуем» превращается в азартную игру. С git — в безопасный эксперимент.

Хорошая новость: команды git учить не обязательно. Агент умеет git отлично — тебе достаточно намерений.

## Три привычки, которые закрывают 90% потребностей

1. **Начал проект — заведи репозиторий.** Одна фраза агенту: «сделай из этой папки git-репозиторий и закоммить начальное состояние». Агент выполнит git init и первый коммит сам.
2. **Работает — коммить.** Закончил шаг, результат живой? «Закоммить с понятным сообщением, что сделано». Правило простое: коммит после каждого работающего состояния, а не раз в день. Мелкие частые коммиты — это много точек возврата.
3. **Сломал — вернись.** «Покажи, что изменилось с последнего коммита» (агент покажет diff), «откати изменения к последнему коммиту». Вот и вся машина времени.

## Полезно понимать (хотя делает агент)

- **История:** «покажи историю коммитов» — агент выполнит git log и переведёт на человеческий.
- **Сообщения коммитов** пиши по-человечески: «добавил форму заявки», а не «фикс» и не «ааа наконец-то». Через неделю ты по этим сообщениям будешь искать нужную точку.
- **Ветки** — для экспериментов покрупнее: «создай ветку и попробуем в ней другой вариант главной страницы». Не понравилось — выкинули ветку, основная версия не пострадала.

## Чего в коммитах быть НЕ должно

Секретов. Пароли, API-ключи, токены — никогда не должны попадать в git: история помнит всё, даже удалённое позже. Ключи живут в отдельном файле (обычно .env), который добавлен в исключения (.gitignore). Скажи агенту: «проверь, что секреты не попадают в git» — он настроит.

## Типичное заблуждение

«Git — это для команд программистов, мне одному не нужно». Наоборот: в одиночке некому тебя подстраховать, кроме git. Первый же случай «агент переписал файл, а старая версия была лучше» окупает привычку целиком.

## Что запомнить

- Git — машина времени; команды знает агент, тебе нужны намерения.
- Новый проект → «заведи git-репозиторий». Работает → «закоммить». Сломал → «откати».
- Коммиты — мелкие и частые, сообщения — человеческие.
- Секреты в git не попадают никогда; пусть агент настроит .gitignore и .env.
