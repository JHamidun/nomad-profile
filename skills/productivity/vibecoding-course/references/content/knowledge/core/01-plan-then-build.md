# Сначала план, потом код

> Атом базы знаний курса. Наставник пересказывает нужный кусок точечно.

Самая дорогая ошибка вайбкодинга — агент быстро и качественно решает не ту задачу. Лекарство простое: разделить «понять и спланировать» и «делать». Я на этом спотыкался сам: пока не начал требовать план до кода, половина сессий уходила на переделки.

## Цикл из четырёх тактов

1. **Осмотреться.** Пусть агент сначала изучит, что есть: «прочитай эти файлы и расскажи, как это устроено. Пока ничего не меняй». В Claude Code для этого есть отдельный Plan Mode (агент читает и думает, но не трогает файлы) — но и просто попросить «сначала без изменений» работает везде, включая Codex.
2. **План.** «Составь план: 3–5 шагов, каждый заканчивается чем-то проверяемым. Запиши в PLAN.md». Читаешь план глазами. Это твоя главная точка контроля: править план дёшево, править готовый код — дорого.
3. **Делать по шагу.** «Делай шаг 1». Посмотрел результат — «делай шаг 2». Не «делай всё сразу»: так ты замечаешь съезд с курса на первом шаге, а не на пятом.
4. **Зафиксировать.** Шаг работает — коммит в git (об этом отдельный атом). Потом следующий.

## Когда план не нужен

Честно: не всегда. Мелочь с ясным объёмом — поправить опечатку, поменять текст кнопки, добавить строку — проси сделать сразу, без церемоний. План нужен, когда ты не уверен в подходе, когда затрагивается несколько файлов или когда ты в чужом/незнакомом проекте.

## Признаки хорошего плана

- 3–5 шагов, не 15. План из 15 шагов — это на самом деле три задачи, разбей.
- Каждый шаг заканчивается проверяемым состоянием: «страница открывается», «файл создаётся», «тест проходит».
- Первый шаг — самый маленький и самый быстрый к «что-то уже работает». Работающий скелет за 10 минут лучше идеальной архитектуры за час.

## Типичное заблуждение

«План — бюрократия, агент и так умный». Агент умный, но он не телепат: без плана он заполнит пробелы своими предположениями. План — это не для агента, это для тебя: единственный момент, когда ты дёшево контролируешь направление.

## Что запомнить

- Разделяй: осмотреться → план → делать по шагу → фиксировать.
- Правка плана стоит минуту, правка результата — час.
- Мелочи делай без плана; план — для нового, многофайлового, непонятного.
- Хороший план: 3–5 шагов, каждый проверяем, первый — быстрый к работающему скелету.
