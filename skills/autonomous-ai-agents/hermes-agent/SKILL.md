# Самоуправление агента Nomad

Этот навык — встроенное руководство по управлению собственной конфигурацией, профилями, расписаниями, каналами связи и роем под-агентов Nomad.

---

## 1. Профили и рабочее окружение

Каждый профиль изолирует настройки (`config.yaml`), переменные окружения (`.env`), память (`memories/`), историю сессий (`state.db`), навыки (`skills/`) и плагины (`plugins/`).

### Основные команды управления профилями
```bash
# Список установленных профилей
hermes profile list

# Просмотр подробной сводки по профилю nomad
hermes profile show nomad

# Установка или обновление профиля из каталога пакета
hermes profile install package/ -y
hermes profile update nomad -y
```

### Работа с конфигурацией профиля
```bash
# Чтение и запись ключей config.yaml в профиле nomad
hermes -p nomad config get plugins.enabled
hermes -p nomad config set display.skin nomad
hermes -p nomad config set dashboard.theme nomad
```

## 2. Навыки и наборы навыков (Skill Bundles)

Навыки хранятся в `<HERMES_HOME>/skills/` и во внешних каталогах из `skills.external_dirs`.
Маркер `.no-bundled-skills` в корне профиля отключает автоматический засев сторонних встроенных навыков при обновлении.

### Инструменты работы с навыками
- `skills_list()` — список доступных навыков и категорий.
- `skill_view(name)` — загрузка полной инструкции навыка (`SKILL.md`) или вложенных справочников.
- `skill_manage(action, ...)` — создание и обновление пользовательских навыков.

### Наборы навыков (`/bundle`)
Наборы навыков в `<HERMES_HOME>/skill-bundles/*.yaml` позволяют одним слэш-вызовом подключить сразу несколько связанных навыков и общую рабочую инструкцию:
```bash
hermes -p nomad bundles list
hermes -p nomad bundles show backend-dev
```

## 3. Планировщик задач (Cron)

Для регулярных проверок, отчётов и автономного мониторинга используй встроенные инструменты планировщика:
- `cronjob(action="list")` — список активных и приостановленных задач.
- `cronjob(action="create", schedule="0 9 * * 1-5", prompt="...", description="...")` — постановка задачи по расписанию.
- `cronjob(action="pause" | "resume" | "delete", job_id="...")` — управление жизненным циклом задачи.

---

## 4. Делегирование и рой воркеров

Когда задача распадается на независимые подзадачи (исследование, написание модулей, проверка тестов):
1. Используй `delegate_task` для запуска изолированных дочерних сессий с чётким контрактом входа и выхода.
2. Не смешивай в одной подзадаче правку пересекающихся файлов.
3. Проверяй результаты каждого воркера запуском тестов и проверочных скриптов перед сборкой итогового ответа.

---

## 5. Память и поиск по сессиям

- `memory(action="add" | "replace" | "remove", target="memory" | "user", ...)` — сохранение устойчивых фактов о проекте, предпочтениях владельца и принятых архитектурных решениях.
- `session_search(query="...")` — полнотекстовый поиск по прошлым диалогам для восстановления контекста и истории решений.
